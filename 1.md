# What is Caching and why do we need it? 🚀

Imagine you're building an E-Commerce application. Your Products page displays hundreds of products.

Every time a user opens the Products page, your application sends a request to the Product Service.

Client(browser) → Product Service → Database

Initially, everything works fine. But as your application grows, thousands of users start visiting the Products page every minute.

Now every request results in a database query.

More users = More database reads.

This increases:

- Database load
- Response time for requests
- Infrastructure cost

Now, if you think about this,

Do products really change every second?

Probably not.

Most products remain unchanged for hours or even days. So why query the database for the same data on every request?

This is where Caching comes in.

Caching is the process of storing frequently accessed data in a fast storage layer so it can be served quickly without repeatedly querying the primary database.

Instead of this:

Client(browser) → Product Service → Database

We do:

Client(browser) → Product Service → Check in Cache → if present(Cache Hit) → Respond back with data, no need to query database

Cache Hit
The requested data already exists in the cache. The service returns it immediately without querying the database.

Cache Miss 
The data isn't in the cache. The service:

> Fetches the data from the database.
> Stores it in the cache.
> Returns the response to the client.

Future requests for the same data become Cache Hits.

Advantages of Caching
✅ Faster response times
✅ Reduced database load
✅ Lower infrastructure costs
✅ Better scalability

Cache Invalidation
The biggest challenge is Cache Invalidation.

What happens if a product's price changes but the cache still contains the old price?
Users will see stale data.

That's why every caching strategy needs a plan for when to update or remove cached data.

Common cache implementations

- Redis
- Memcached
- In-Memory Cache
- CDN Cache
- Browser Cache

Redis is one of the most popular tools for implementing distributed caching, but caching itself is a concept, not a technology.
