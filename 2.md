# Caching Strategies

Caching Strategies define when and how data is stored, read, updated, and deleted from the cache. The common Strategies are

> Read Strategies

Cache Aside - Server manages the cache
Client sends a request. Server first queries the cache. If found -> CACHE HIT, return from cache. If not -> CACHE MISS, return the data from DB and update the cache.

Read Through - Read happens from the cache
Cache sits between the server and database and the server never queries the database directly. Cache keeps itself updated always.

> Write Strategies

Write Through - Write in cache first, then in DB.
Every write/update data operation happens on the cache first, then on the database.

Write Around - Write to DB, read from cache
Every write happens on the DB; the server updates the cache whenever there is a Cache Miss.

Write Back - Always on cache, once on DB
Every write happens on the cache; once in a while, the cache updates the DB with all the operations.
