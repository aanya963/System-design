# Caching Strategies

Caching Strategies define when and how data is stored, read, updated, and deleted from the cache. The common Strategies are

> Read Strategies

Cache Aside - Server manages the cache
Client sends a request. Server first queries the cache. If found -> CACHE HIT, return from cache. If not -> CACHE MISS, return the data from DB and update the cache.

Read Through - Read happens from the cache
Cache sits between the server and database and the server never queries the database directly. Cache keeps itself updated always.

> Write Strategies

Write Through - Write in cache first, then in DB.
Every write/update data operation happens on the cache first, then on the database.

Write Around - Write to DB, read from cache
Every write happens on the DB; the server updates the cache whenever there is a Cache Miss.

Write Back - Always on cache, once on DB
Every write happens on the cache; once in a while, the cache updates the DB with all the operations.



# Types of Cache by Architectural Layer
This dimension defines where the cache sits along the request-response lifecycle, from the client's screen down to the data storage.
1. Client-Side / Browser Cache: Stores static HTML, CSS, JavaScript, and media assets directly on the user's device. It uses HTTP headers like Cache-Control to eliminate network requests entirely for repeat visits.
2. CDN (Content Delivery Network) Cache: Distributed edge servers cache static and public API content close to users geographically. Major platforms like Cloudflare and Akamai handle media delivery at this tier.
3. Reverse Proxy / Load Balancer Cache: Infrastructure components like NGINX or Varnish sit in front of application servers. They cache common API responses to protect backend applications from duplicate traffic.
4. Application Cache: Operates within the backend service layer to store the results of complex database queries, user session data, or expensive computations.
5. Database Cache: Internal memory buffers (such as buffer pools) allocated within database engines like PostgreSQL or MySQL. They hold hot table rows and index pages in RAM to minimize slow disk I/O operations.
