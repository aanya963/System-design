# What is HTTP and how does it work?

- HTTP stands for Hypertext Transfer Protocol and is used by the client and server to communicate and transfer data between each other. 
- HTTP contains a set of rules on how communication is established, requests are formatted, and responses are sent. 

Every HTTP request contains:
Method - what action to perform
URL - address of the resource
Headers - Request metadata
Body - Data sent by the client to the server

Every HTTP response contains:
Status Code - result of the request
Headers - metadata of the response
Body - requested data

HTTP methods
GET - get data
POST - create new data
PUT - update/replace data
PATCH - update data in place
DELETE - delete data

HTTP status codes
200 - OK
201 - Created
301 - Moved
304 - Not Modified
400 - Bad Request
401 - Unauthorized
404 - Not Found
500 - Internal Server Error
503 - Service unavailable

- Every HTTP request is stateless. 
- HTTPS is a secure version of HTTP. In HTTPS, data is encrypted before being sent by the client. 
- HTTP uses TCP underneath


RFC 10008 – The HTTP QUERY Method, published in June 2026. It introduces a brand-new HTTP method called QUERY.

"I want to retrieve data (like GET), but my query is too large or complex to fit in the URL."

An HTTP method is idempotent if the intended effect on the server of making a single request is the same as the effect of making several identical requests.

# Option 1: GET
GET /employees?department=IT&salary>50000&experience=5
But what if your search becomes huge?
Putting lot into a URL becomes ugly.


# Option 2: POST
Most APIs today do
POST /employees/search
Body:
{
   ...
}
But...
POST means "This request may change server state."
            Even if your endpoint only searches.

Therefore
    caches don't work well
    retries become tricky
    proxies treat it differently

# The new method QUERY
QUERY /employees
Content-Type: application/json
{
   ...
}
The search parameters go inside the body, just like POST...
but the operation is declared as Safe and Idempotent.
    Reading ✔
    Searching ✔
    Filtering ✔
    Aggregating ✔
    Reporting ✔

Exactly like GET.
# Idempotent An HTTP method is idempotent if the intended effect on the server of making a single request is the same as the effect of making several identical requests.


HTTP never officially defined semantics for GET request bodies.

Many proxies ignore them.

Many frameworks don't support them.

Therefore the RFC creates a proper method instead


POST usually means

"Something may change on the server."

GET means

"Read only."

QUERY solves this confusion.

It means

"Read only, but using a request body."


| Code    | Meaning       | Example                    |
| ------- | ------------- | -------------------------- |
| **1xx** | Informational | `100 Continue`             |
| **2xx** | Success       | `200 OK`                   |
| **3xx** | Redirection   | `301`, `302`               |
| **4xx** | Client error  | `400`, `401`, `403`, `404` |
| **5xx** | Server error  | `500`, `502`, `503`        |


**200 OK -> Request succeeded

**301 / 302 -> Go somewhere else

**400 Bad Request -> Your request is invalid

**401 Unauthorized -> Authentication is required/failed

**403 Forbidden -> I understand you, but you're not allowed

**404 Not Found -> The requested resource doesn't exist

**500 Internal Server Error -> Something went wrong on the server
