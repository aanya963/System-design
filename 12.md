# Idempotent

An operation is **idempotent** if performing it multiple times has the **same intended effect on the server's state** as performing it once.

Example:

PUT /user/123
{
  "name": "John"
}

Send it once:

name = John

Send it 10 times:
name = John

The final state is still the same.

Therefore, **PUT is idempotent**.

> Idempotent HTTP methods

GET
HEAD
PUT
DELETE
OPTIONS
TRACE

are considered idempotent.

`POST` is **not generally idempotent**.
POST /orders
Send it once: Order #1 created
Send it again: Order #2 created

So repeating the request can produce another effect.
Idempotent does **not** necessarily mean: "The response will be exactly the same."
It means the **intended server state/effect** is the same after repeated requests.
