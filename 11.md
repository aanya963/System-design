# Database Sharding vs Replication
Database Sharding is a database scaling technique where data is partitioned across multiple servers or databases, known as shards. Each shard holds a subset of the entire dataset. This method distributes the load by horizontally splitting the data, meaning each shard manages a different piece of the data.
- Horizontal data partitioning.
- Shards hosted on different servers.
- Independent scaling per shard.
- Shards can be geographically distributed.

Database replication is the process of copying and maintaining database data across multiple servers or locations. It ensures that there are multiple replicas of the same data, which improves data availability, fault tolerance, redundancy, and can enhance read performance.
- Full data copies on multiple servers.
- Can be synchronous (immediate) or asynchronous (eventual).
- Enhances availability and disaster recovery.
- Supports read scaling and failover.

> There are typically two main types of replication:
- Master-Slave Replication (Primary-Replica): One primary server handles all writes, while replicas sync data for read operations.
- Master-Master Replication (Multi-Primary): Multiple servers handle both reads and writes with synchronized data across nodes.
