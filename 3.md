# Content Delivery Network (CDN)
A CDN (Content Delivery Network) is essentially a distributed network of caches/servers located in different geographical regions.

A CDN (Content Delivery Network) is a network of globally distributed servers that stores and delivers website/app content like images, videos, CSS, JS, and files from the nearest edge server, so users get faster load time, lower latency, and better availability, while the main origin server load also reduces.

- Reduces latency by serving content from the nearest edge server.
- Improves performance with faster load times and better user experience.
- Enhances availability and scalability by handling traffic spikes and failures.

Types of Content Delivered by CDN
1. Static Content
2. Dynamic Content


Types of CDN
CDNs can be classified into several types based on their architecture and functionality:
1. Public CDNs
2. Private CDNs
3. Peer-to-Peer (P2P) CDNs
4. Hybrid CDNs
5. Push CDNs
6. Pull CDNs



# 🌐 DNS, Firewall, NGINX, CORS & HTTP — Notes

1. DNS — Domain Name System

**DNS = Domain Name System**

Its job is to translate a human-readable domain name into an IP address.

> Example:
google.com
    ↓
DNS
    ↓
142.250.x.x

Your browser needs the IP address to know **which server to connect to**.

2. DNS A Record
An A record maps a domain name → **IPv4 address**.

> Example:
api.example.com
       ↓
   54.175.148.96

> Think:
A record = Name → IPv4 address**
Example: example.com → 123.45.67.89

---

3. DNS CNAME Record
CNAME = Canonical Name
A CNAME maps one domain name → **another domain name**.

> Example:
api.example.com
       ↓
backend.example.com
       ↓
54.175.148.96

A Record:
api.example.com → 54.175.148.96

CNAME:
api.example.com → backend.example.com

> Easy way to remember

**A → IP address**

**CNAME → another domain name**

> Important point

**DNS is not really a step where the HTTP request "passes through" the DNS server.**
DNS happens to **find the IP address first**.
Then the browser makes the actual HTTP/HTTPS connection to that IP.

5. Firewall

A **firewall controls which network traffic is allowed or blocked**.

For example, your server might allow:
Port 22  → SSH
Port 80  → HTTP
Port 443 → HTTPS

and block everything else.

Think:

> Firewall = Security guard at the entrance

Example:
Internet
   ↓
Firewall
   ↓
Allowed? ── No → ❌ Block
   │
  Yes
   ↓
Server

> Example
If your application is running on: localhost:3001
that does **not automatically mean the internet can access port 3001**.
NGINX can receive public traffic on port 443 and forward it internally to: localhost:3001

6. NGINX

**NGINX** is commonly used as a **reverse proxy**.
Suppose your Node.js application is running on: localhost:3001
But users shouldn't directly access: example.com:3001

Instead:

User
 ↓
https://example.com
 ↓
NGINX
 ↓
localhost:3001
 ↓
Node.js application

NGINX receives the public request and forwards it to your application.

> Why use NGINX?

It can handle things like:

* Reverse proxying
* HTTPS/TLS termination
* Routing
* Serving static files
* Load balancing
* Security-related configuration
