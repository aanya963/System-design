# Database 101

Every application needs a place to store data. For an E-Commerce application, you will need a storage solution to store details about users, products, orders, and messages. This is what a Database is for.

A Database is an organised collection of data that can be stored, retrieved, updated, and deleted reliably — even after the server restarts or crashes.

Client → Server → Database

A Server does not store data; it is only responsible to read/update/delete data from a database.

A Database supports four types of operations - Create, Read, Update, Delete. Also called CRUD operations.

Types of Databases

- Relational Databases
- Non-Relational Databases
- Graph Databases
- Object Oriented Databases
- Hierarchical Databases
- Vector Databases

What are the types of Databases?

Relational Databases

- Data is stored in rows and columns. Think of it as an Excel sheet.
- Data follows a structure and is consistent.

Examples:
MySQL, PostgreSQL, Oracle, etc

Non-Relational Databases

- Designed to handle large volumes of unstructured or semi-structured data.
- Data cannot be stored inside a table.
- Based on how the data is stored, Non-Relational databases can be further divided into

Document Databases
- Data stored in JSON-like documents. 
- Example: MongoDB

Key-Value Databases
- Data stored in simple key-value pairs. 
- Example: Redis and DynamoDB

Column-Oriented Databases
- Data stored in the form of columns
- Example: Apache Cassandra

Graph Databases
- A form of database used to store relationships between data
- Data is represented in the form of nodes and edges.
- Example: Neo4j

Object Oriented Databases
- Data is stored in form of Objects and follows OOPs principles
- Example: ObjectDB

Vector Databases
- Data is stored in form of Vector Embeddings
- Used for similarity search
- Basis of RAG pipelines and semantic searchs
