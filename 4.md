# Database 101

## 1. What is a Database?

Every application needs a place to store and manage data.

For example, an E-Commerce application** needs to store information about:

* Users
* Products
* Orders
* Payments
* Messages

A Database is an organised collection of data that allows applications to store, retrieve, update, and delete data reliably.

The data remains available even if the server **restarts or crashes**.

### Basic Architecture
* **Client** — Sends requests to the application.
* **Server** — Processes requests and performs business logic.
* **Database** — Stores and manages the application's data.

> Important: A server generally does not act as the permanent storage for application data. It is responsible for reading from and writing to the database.

# 2. CRUD Operations
A database supports four fundamental operations, commonly known as CRUD:

| Operation  | Meaning                | Example               |
| ---------- | ---------------------- | --------------------- |
| **Create** | Add new data           | Create a new user     |
| **Read**   | Retrieve existing data | Get a user's details  |
| **Update** | Modify existing data   | Update a user's email |
| **Delete** | Remove data            | Delete a user         |

So, **CRUD = Create + Read + Update + Delete**.



# 3. Types of Databases
Databases can broadly be classified into two categories:

1. **Relational Databases**
2. **Non-Relational Databases**

Non-relational databases can further be divided into different types based on how they store and organise data.
Databases
│
├── Relational Databases
│
└── Non-Relational Databases
    │
    ├── Document Databases
    ├── Key-Value Databases
    ├── Column-Oriented Databases
    ├── Graph Databases
    ├── Object-Oriented Databases
    └── Vector Databases


# 4. Relational Databases
A **Relational Database** stores data in the form of **tables**, which consist of **rows and columns**.

You can think of it as an **Excel spreadsheet**, where:
* **Table** → Spreadsheet
* **Row** → Individual record
* **Column** → Attribute/property

Relational databases generally follow a **predefined structure (schema)**, which helps maintain consistency and relationships between data.

### Examples
* MySQL
* PostgreSQL
* Oracle
* Microsoft SQL Server


# 5. Non-Relational Databases
**Non-Relational Databases**, commonly called **NoSQL databases**, do not primarily organise data using traditional relational tables.

They are often designed to handle **large volumes of structured, semi-structured, or unstructured data** and can provide flexible data models.

Different types of non-relational databases store data in different ways.



5.1 Document Databases
Document databases store data as **documents**, usually in a JSON-like format.

Documents can have flexible structures, meaning two documents in the same collection do not necessarily need to contain exactly the same fields.

Example
**MongoDB**


## 5.2 Key-Value Databases
Key-value databases store data as simple **key-value pairs**.
Key        → Value
user:101   → Alice
user:102   → Bob


They are particularly useful when you need to quickly retrieve a value using a known key.

Examples
* Redis
* Amazon DynamoDB

## 5.3 Column-Oriented Databases

Column-oriented databases organise and store data by **columns** rather than traditional row-based storage.

They are useful for certain large-scale workloads, especially when applications need to handle huge amounts of data across many machines.
Example : Apache Cassandra


# 6. Graph Databases
Graph databases are designed to represent and query **relationships between data**.

Data is commonly represented using:

* **Nodes** → Entities
* **Edges** → Relationships between entities
* **Properties** → Information about nodes or relationships

Example
Alice ──FRIENDS_WITH──> Bob
  │
  └──PURCHASED──> Product A


Graph databases are useful for applications where **relationships are as important as the data itself**.

# 7. Object-Oriented Databases

Object-oriented databases store data in the form of **objects** and are designed around concepts from **Object-Oriented Programming (OOP)**.

Instead of converting objects into tables and rows, applications can work more directly with persistent objects.


# 8. Vector Databases

Vector databases store and search **vector embeddings**.

A vector embedding is a numerical representation of data such as:

* Text
* Images
* Audio
* Other types of content

For example, a sentence can be converted into a vector:

```text
"Database fundamentals"
        ↓
[0.12, -0.45, 0.78, 0.21, ...]
```

Vector databases are primarily used for **similarity search** — finding data that is semantically similar to a given query.
